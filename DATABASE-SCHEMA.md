# Database Schema — KidLearn Interactive

Version: 0.1
Status: Phase 0.6 Data Foundation

## 1. Purpose

Define the physical Google Sheets data model for KidLearn Interactive so the Apps Script backend, frontend, and future interactive modules share one stable contract.

Design goals:
- Forward-compatible with more grades, subjects, modules, and assessment types.
- Keep content, interaction config, learner identity, and assessment attempts separated.
- Avoid subject-specific columns in core tables.
- Preserve history instead of overwriting important records.
- Allow future migration to a relational database without redesigning entity boundaries.

## 2. General Conventions

### IDs
Use stable string IDs generated by backend logic, not row numbers.

Recommended forms:
- `grade_p4`
- `subject_science_p4`
- `unit_solar_01`
- `lesson_solar_intro`
- `activity_solar_mcq_01`
- `assessment_solar_01`
- `learner_0001`
- UUID-like values for attempts/scores where practical.

### Dates
Store timestamps as ISO 8601 strings in UTC, e.g. `2026-08-30T02:15:00Z`.

### Boolean
Use `TRUE` / `FALSE` consistently.

### Status
Prefer controlled values such as:
- `draft`
- `ready`
- `published`
- `archived`
- `active`
- `inactive`

### JSON fields
Use JSON only for extensible module-specific configuration, never as a substitute for core relational fields.

### Soft delete
Core business/content records should normally be archived or deactivated instead of deleted.

## 4. Detailed Tables

### 4.1 `_Meta`
System metadata and schema versioning.

Columns:
- `key` STRING PK
- `value` STRING REQUIRED
- `description` STRING OPTIONAL
- `updated_at` DATETIME REQUIRED

Seed keys:
- `schema_version`
- `app_name`
- `environment`

### 4.2 `Grades`
- `grade_id` STRING PK
- `name_th` STRING REQUIRED
- `name_en` STRING OPTIONAL
- `level_number` NUMBER REQUIRED
- `sort_order` NUMBER REQUIRED
- `status` ENUM REQUIRED
- `created_at` DATETIME REQUIRED
- `updated_at` DATETIME REQUIRED

### 4.3 `Subjects`
- `subject_id` STRING PK
- `grade_id` STRING FK -> Grades.grade_id
- `name_th` STRING REQUIRED
- `name_en` STRING OPTIONAL
- `description` STRING OPTIONAL
- `icon_asset_id` STRING FK -> Assets.asset_id OPTIONAL
- `sort_order` NUMBER REQUIRED
- `status` ENUM REQUIRED
- `created_at` DATETIME REQUIRED
- `updated_at` DATETIME REQUIRED

### 4.4 `Units`
- `unit_id` STRING PK
- `subject_id` STRING FK -> Subjects.subject_id
- `title` STRING REQUIRED
- `description` STRING OPTIONAL
- `sort_order` NUMBER REQUIRED
- `status` ENUM REQUIRED
- `created_at` DATETIME REQUIRED
- `updated_at` DATETIME REQUIRED

### 4.5 `Lessons`
- `lesson_id` STRING PK
- `unit_id` STRING FK -> Units.unit_id
- `title` STRING REQUIRED
- `summary` STRING OPTIONAL
- `cover_asset_id` STRING FK -> Assets.asset_id OPTIONAL
- `estimated_minutes` NUMBER OPTIONAL
- `difficulty` ENUM OPTIONAL (`easy`,`normal`,`challenging`)
- `sort_order` NUMBER REQUIRED
- `status` ENUM REQUIRED
- `version` NUMBER REQUIRED DEFAULT 1
- `created_at` DATETIME REQUIRED
- `updated_at` DATETIME REQUIRED

### 4.6 `ContentBlocks`
Reusable renderer-driven lesson content.

- `block_id` STRING PK
- `lesson_id` STRING FK -> Lessons.lesson_id
- `block_type` ENUM REQUIRED (`text`,`image`,`video`,`callout`,`example`,`key-point`,`activity-link`)
- `title` STRING OPTIONAL
- `body` STRING OPTIONAL
- `asset_id` STRING FK -> Assets.asset_id OPTIONAL
- `activity_id` STRING FK -> Activities.activity_id OPTIONAL
- `config_json` JSON OPTIONAL
- `sort_order` NUMBER REQUIRED
- `status` ENUM REQUIRED
- `version` NUMBER REQUIRED DEFAULT 1
- `created_at` DATETIME REQUIRED
- `updated_at` DATETIME REQUIRED

### 4.7 `Activities`
Core metadata for every interactive activity.

- `activity_id` STRING PK
- `lesson_id` STRING FK -> Lessons.lesson_id
- `module_id` STRING FK -> Modules.module_id
- `title` STRING REQUIRED
- `instructions` STRING OPTIONAL
- `mode_support` STRING REQUIRED (`learn`,`assessment`,`learn,assessment`)
- `config_id` STRING FK -> ActivityConfigs.config_id
- `max_score` NUMBER OPTIONAL
- `sort_order` NUMBER REQUIRED
- `status` ENUM REQUIRED
- `version` NUMBER REQUIRED DEFAULT 1
- `created_at` DATETIME REQUIRED
- `updated_at` DATETIME REQUIRED

### 4.8 `ActivityConfigs`
Module-specific extensible configuration.

- `config_id` STRING PK
- `activity_id` STRING FK -> Activities.activity_id UNIQUE
- `schema_version` STRING REQUIRED
- `config_json` JSON REQUIRED
- `checksum` STRING OPTIONAL
- `created_at` DATETIME REQUIRED
- `updated_at` DATETIME REQUIRED

Supports composite modules such as LearnQuest.

- `stage_id` STRING PK
- `parent_activity_id` STRING FK -> Activities.activity_id
- `stage_type` ENUM REQUIRED (`content`,`activity`,`summary`)
- `ref_id` STRING OPTIONAL
- `title` STRING OPTIONAL
- `sort_order` NUMBER REQUIRED
- `score_weight` NUMBER OPTIONAL
- `required` BOOLEAN REQUIRED DEFAULT TRUE
- `config_json` JSON OPTIONAL
- `status` ENUM REQUIRED

### 4.10 `Assessments`
Turns an assessment-capable activity into a scored assessment definition.

- `assessment_id` STRING PK
- `activity_id` STRING FK -> Activities.activity_id
- `title` STRING REQUIRED
- `allow_multiple_attempts` BOOLEAN REQUIRED
- `max_attempts` NUMBER OPTIONAL
- `show_score_after_submit` BOOLEAN REQUIRED
- `show_answers_after_submit` BOOLEAN REQUIRED
- `time_limit_seconds` NUMBER OPTIONAL
- `passing_percent` NUMBER OPTIONAL
- `available_from` DATETIME OPTIONAL
- `available_until` DATETIME OPTIONAL
- `status` ENUM REQUIRED
- `version` NUMBER REQUIRED DEFAULT 1
- `created_at` DATETIME REQUIRED
- `updated_at` DATETIME REQUIRED

### 4.11 `Learners`
Lightweight learner identity only.

- `learner_id` STRING PK
- `learner_code` STRING UNIQUE REQUIRED
- `display_name` STRING REQUIRED
- `grade_id` STRING FK -> Grades.grade_id OPTIONAL
- `identity_hint` STRING OPTIONAL
- `pin_hash` STRING OPTIONAL (future)
- `status` ENUM REQUIRED
- `created_at` DATETIME REQUIRED
- `updated_at` DATETIME REQUIRED

Do not store unnecessary sensitive information.

### 4.12 `Attempts`
One row per assessment attempt.

- `attempt_id` STRING PK / idempotency key
- `learner_id` STRING FK -> Learners.learner_id
- `assessment_id` STRING FK -> Assessments.assessment_id
- `assessment_version` NUMBER REQUIRED
- `started_at` DATETIME REQUIRED
- `submitted_at` DATETIME OPTIONAL
- `status` ENUM REQUIRED (`started`,`submitted`,`save_failed`,`cancelled`)
- `client_session_id` STRING OPTIONAL
- `created_at` DATETIME REQUIRED
- `updated_at` DATETIME REQUIRED

Attempts are append-oriented; never overwrite prior attempts to represent a new attempt.

### 4.13 `Scores`
Official score persistence after backend confirmation.

- `score_id` STRING PK
- `attempt_id` STRING FK -> Attempts.attempt_id UNIQUE
- `score` NUMBER REQUIRED
- `max_score` NUMBER REQUIRED
- `percentage` NUMBER REQUIRED
- `result_status` STRING OPTIONAL
- `saved_at` DATETIME REQUIRED
- `score_payload_json` JSON OPTIONAL (reserved future aggregate metadata)

V1 reporting uses the total score only.

### 4.14 `Assets`
Registry for Google Drive media.

- `asset_id` STRING PK
- `drive_file_id` STRING UNIQUE REQUIRED
- `asset_type` ENUM REQUIRED (`image`,`audio`,`video`,`pdf`,`worksheet`,`other`)
- `title` STRING REQUIRED
- `alt_text` STRING OPTIONAL
- `mime_type` STRING OPTIONAL
- `usage` STRING OPTIONAL
- `source_folder` STRING OPTIONAL
- `status` ENUM REQUIRED
- `version` NUMBER REQUIRED DEFAULT 1
- `created_at` DATETIME REQUIRED
- `updated_at` DATETIME REQUIRED

Frontend should resolve assets by `asset_id`, not hard-coded Drive URLs.

### 4.15 `LearningObjectives`

### 4.17 `Tags`
- `tag_id` STRING PK

- `audit_id` STRING PK

## 5. Relationship Map

```text
Grades
 └─ Subjects
     └─ Units
         └─ Lessons
             ├─ ContentBlocks
             └─ Activities ── ActivityConfigs
                    ├─ ActivityStages
                    └─ Assessments

Learners ── Attempts ── Scores
               │
               └─ Assessments

Assets <- Subjects / Lessons / ContentBlocks / Activities
Modules <- Activities
LearningObjectives <-> LessonObjectives <-> Lessons
Tags <-> ContentTags <-> content entities
```

## 6. Query / Lookup Strategy for Google Sheets

Google Sheets is not a relational database, so Apps Script must maintain lookup maps in memory per request where practical.

Recommended patterns:
- Read header row once and map column names to positions.
- For small reference sheets (`Grades`, `Modules`, `AppConfig`), cache values with Apps Script CacheService.
- For lookups by primary key, build in-memory `Map` objects after bounded reads.
- Avoid repeated `getRange()` calls inside loops.
- Use batched reads/writes (`getValues`, `setValues`).
- For append-oriented sheets (`Attempts`, `Scores`, `AuditLog`), append in one operation and validate uniqueness before write.

Expected lookup keys:
- `learner_code`
- `attempt_id`
- `assessment_id`
- `activity_id`
- `lesson_id`
- `drive_file_id`

## 7. Integrity Rules

Apps Script is responsible for enforcing constraints Google Sheets cannot enforce natively:
- PK uniqueness.
- FK existence.
- Valid enum values.
- Required fields.
- Assessment availability window.
- Attempt limits.
- One official `Scores` row per `attempt_id`.
- `attempt_id` idempotency on retry.
- Prevent publishing content with dangling references.

## 8. Versioning & Migration

### Schema version
Stored in `_Meta` key `schema_version`.

Initial version: `1.0.0`.

### Content versions
`Lessons`, `Activities`, `Assessments`, and `Assets` carry a numeric version.

### Migration rule
Never silently rename/delete a column used by production code.

For breaking changes:
1. Update `DATABASE-SCHEMA.md`.
2. Increment schema version.
3. Add a migration function in Apps Script.
4. Back up the spreadsheet before migration.
5. Migrate data deterministically.
6. Validate row counts and required references.
7. Record migration in `_Meta` and `AuditLog`.

## 9. Capacity Guardrails

Google Sheets is appropriate for the personal-project V1/V2 scale, but should not be treated as an unlimited transactional database.

Migration to a database should be considered if any of these become routine:
- very high concurrent assessment submissions
- hundreds of thousands of attempt/score rows with slow reporting
- complex per-question analytics
- transactional workflows requiring strong locking
- large-scale multi-tenant usage

The entity separation in this schema is intentionally designed so such migration can occur table-by-table later.
